💡 Playbook: Proyecto Integrador T2 - Sesión 2

⏱️ 40:00

Actividades

  • 📝 Comando Central
  • 1. Briefing
  • 2. Vibe Coding

📝 De un Vistazo: Comando Central

Sesión de Construcción: Orquestación de Agentes y Lógica de Python.

🎯 Objetivo de Aprendizaje

Los estudiantes podrán: Traducir una arquitectura de agentes (ReAct/Function Calling) en un prototipo funcional utilizando Python y automatización avanzada, aplicando depuración lógica en flujos de IA.

🤖 Prompt de Referencia para XOLO (Solo para Maestro)

⚠️ NOTA: XOLO actúa como Arquitecto de IA y Desarrollador Python automáticamente. Usar solo en emergencia: 
Actúa como Arquitecto de Software experto en Python y Orquestación de Agentes. Ayúdame a generar la estructura de mi agente basado en mi 'Vibe Formal', explica cómo funcionan las llamadas a funciones (Function Calling), la lógica ReAct y asísteme en la depuración de la lógica de programación y flujos de datos en Make.com o Python. Sé técnico pero asegúrate de que el alumno entienda el flujo de razonamiento de la IA.

⚡ Puntos Esenciales de la Misión

🏗️

Concepto Clave

Arquitectura de Agentes: Implementar el ciclo de Pensamiento-Acción-Observación (ReAct) en un entorno digital.

🔧

Habilidad Técnica

Python y Automatización: Escribir scripts de integración y configurar Function Calling para extender las capacidades de la IA.

🚩

Táctica: Taming the Genie

No solo generar código, sino ""domar"" la lógica del agente, entendiendo sus decisiones y documentando los ajustes en el razonamiento.

💬

Interacción con XOLO

XOLO actúa como ""Arquitecto de IA"". Genera la lógica base del agente y guía al alumno en la depuración de prompts y scripts.

📦 Checklist de Materiales

🗓️ Secuencia de la Misión (40 min)

1
Briefing de Arquitectura 5 min

Enfoque en pasar del diseño de flujo a la implementación lógica.

2
Vibe Coding y Lógica de Agentes 15 min

Generación de scripts de Python y configuración de herramientas con Xolo.

3
Implementación y Depuración de Flujos 15 min

Pruebas de API, conexión de módulos en Make y corrección de bucles lógicos.

4
Cierre y Reflexión 5 min

Revisión final de la Bitácora de Mejoras y eficiencia del agente.

🚨 Resolución Rápida de Problemas

  • Si XOLO genera funciones demasiado complejas: Pide al alumno que le diga: ""Divide esta función en pasos más pequeños y explícame la lógica del retorno de datos"".
  • Si la API falla: Verifica las claves de autenticación y los límites de cuota en el dashboard correspondiente.
  • Si el agente entra en bucle: Revisa el prompt de sistema (System Prompt) para asegurar que tiene instrucciones claras de salida o parada.

🚀 Actividad 1: Briefing de Arquitectura

⏱️ 5:00

👨‍🏫 Rol del Maestro

  • Explicar que hoy el diseño arquitectónico de la sesión 1 se convierte en un sistema funcional.
  • Introducir el concepto de ""Taming the Genie"" aplicado a la orquestación: dominar la autonomía de la IA.
  • Presentar la Bitácora de Mejoras como el registro de iteraciones del agente.

👦 Rol del Alumno

  • Preparar su ""Vibe Formal"" (diagrama de flujo o arquitectura) de la sesión anterior.
  • Entender que la meta es crear un flujo donde la IA tome decisiones basadas en herramientas (tools).

📊 Diapositiva 1: De la Arquitectura al Código

🎯 Misión: Materializar tu Agente Inteligente.

Hoy programamos la lógica, conectamos las APIs y depuramos el razonamiento.

🧠 Actividad 2: Vibe Coding y Lógica de Agentes

⏱️ 15:00

👨‍🏫 Rol del Maestro

  • Supervisar que los prompts a Xolo definan claramente las ""Tools"" o funciones que el agente puede usar.
  • Asegurar que los alumnos definan el framework (ReAct, cadenas de LangChain o scripts puros de Python).

🤖 Rol de XOLO

✅ ARQUITECTO DE IA

  • Traduce el diseño de los alumnos a código Python funcional.
  • Explica cómo integrar Function Calling para que el agente interactúe con el mundo exterior.

👦 Rol del Alumno

  • Usar Vibe Coding para generar el script principal del agente o la estructura de automatización.
  • Cuestionar a Xolo sobre la lógica de toma de decisiones (¿Por qué el agente elegiría esta herramienta?).
  • Registrar la primera versión de la arquitectura lógica en su bitácora.

📊 Diapositiva 2: Orquestando al Genio

💬 Prompt con XOLO:

""Xolo, basado en mi arquitectura de [Proyecto], genera un script en Python que use un agente ReAct. El agente debe poder llamar a la función [Nombre de Función] cuando detecte [Condición]. Explícame el flujo de Pensamiento (Thought).""

⚠️ Regla de Oro: Si no entiendes el flujo de decisión del agente, no tienes el control. ¡Dómalo!

💡 Actividad 3: Implementación y Depuración de Flujos

⏱️ 15:00

👨‍🏫 Rol del Maestro

  • Asistir en errores de sintaxis en Python o errores de conexión en Make.com.
  • Fomentar la depuración de prompts: si el agente alucina, hay que ajustar el System Prompt.

🤖 Rol de XOLO

✅ CONSULTOR TÉCNICO

  • Analiza logs de error para identificar fallos en las llamadas a funciones.
  • Sugiere mejoras en el manejo de excepciones para que el agente no se detenga ante un error.

👦 Rol del Alumno

  • Configurar el entorno (Python/Make) y cargar los scripts generados.
  • Realizar pruebas de ejecución: enviar inputs al agente y observar sus outputs y acciones.
  • Documentar cada fallo lógico (alucinación, bucle infinito) y cómo ajustaron el código o el prompt.

📊 Diapositiva 3: Debugging del Razonamiento

🛠️ Ciclo de Iteración Digital:

1. Ejecuta -> 2. Observa -> 3. Identifica Fallo Lógico -> 4. Ajusta con Xolo -> 5. Optimiza.

La Bitácora de Mejoras debe mostrar la evolución de la ""inteligencia"" de tu sistema.

⚡ Actividad 4: Cierre y Reflexión

⏱️ 5:00

👨‍🏫 Rol del Maestro

  • Revisar aleatoriamente las Bitácoras de Mejoras, enfocándose en cómo resolvieron problemas lógicos.
  • Reforzar que un buen desarrollador de IA es aquel que sabe guiar el razonamiento de la máquina.

👦 Rol del Alumno

  • Asegurar que su código esté comentado y guardado en su repositorio o carpeta del proyecto.
  • Participar en el Think-Pair-Share final sobre la autonomía de su agente.

📊 Diapositiva 4: Bitácora de Mejoras

¿Cuál fue la alucinación o error lógico más complejo y cómo ajustaste el código para ""domarlo""?
